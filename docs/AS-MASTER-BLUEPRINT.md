# 제1장. 정관 — 세 문장

이 사이트의 존재 이유이자 모든 결정의 심판 기준.

1. **자료가 스스로 모인다.** 수집·요약·등록은 자동화 파이프가 한다.
2. **운영자의 손은 최소로.** 목표: 하루 5분, Discord 알림 확인과 승인 버튼. 단, **검수(승인)만은 사람이 한다** — 틀린 숫자 하나가 신뢰 전체를 무너뜨리기 때문.
3. **많은 사람이 본다.** 단 "많이"의 정의는 트래픽이 아니라 **도달과 인용**이다. 필요한 사람(기자·연구자·보좌관·당사자)이 검색으로 반드시 도착하고, "자료: 중독사회"로 인용되는 것.

**포지셔닝 근거** (2026-07-16 조사로 확인된 사실): 중독 전체(알코올·마약·도박·디지털)를, 한국 포함, 최신으로 보여주는 곳은 세계에 없다. WHO는 도박 없음, UNODC는 마약만, EUDA는 유럽만, GDPI는 한국 미포함·2021년 중단, ATLAS-SU는 2014년 중단, 한국은 6개 부처 분산·정보공유 불가. **이 빈자리가 시장이다.**

**차별 자산 두 가지**: ① 학자 30년 + 회복 당사자라는 이중 관점, ② Statory라는 자체 통계 분석 엔진. 특히 ②는 어떤 유사 사이트도 복제할 수 없다.

# 제2장. 사이트 구조 — 4그룹 8페이지

각 페이지는 하나의 질문에 답한다. 질문이 겹치면 페이지가 겹친 것이다(중복 금지의 판정 기준).

## 그룹 1. 데이터 (관측소)

| 페이지 | 답하는 질문 | 상태 |
|---|---|---|
| **소스 지도** /sources | 중독 데이터는 **어디서** 나오나 | ✅ 완성 (23개 소스) |
| **발표 달력** /calendar | **언제** 나오나 | ✅ 완성 (13건 예정 + 미정) |
| **지표** /indicators | 숫자는 **무엇**인가 | M3 — indicators/observations 테이블, 지표당 1페이지(SEO 단위), 모든 수치에 원본 딥링크 |

## 그룹 2. 분석 (생산)

| 페이지 | 답하는 질문 | 상태 |
|---|---|---|
| **분석실** /lab | 우리가 **직접 분석하면** 뭐가 나오나 | 신설 — Statory Lab 중독랩 결과물의 전시장. **복제가 아니라 프록시** (기존 C-6-d1 reports 프록시 패턴 확장). 결과물마다 사용한 지표·소스로 딥링크 + "Powered by Statory" |

축적 구조 두 갈래:
- **정기 시리즈**: 관측소 알림 연동 자동 생산 (예: 대검 월간동향 도착 → 그 달의 시계열 분석 1편. M4 이후). 중독격차 시리즈가 원형.
- **사건 대응**: 정신건강실태조사·국정감사 등 대형 발표 심층 분석.

## 그룹 3. 자료실 (수집)

| 페이지 | 답하는 질문 | 상태 |
|---|---|---|
| **정책문서** /policy | 기관들이 **무엇을 냈나** (산출물 보관소) | 기존 7건 → 초기 일괄 등록 30~50건 + 관측소 알림 연동 자동 등록 |
| **연구자료** /research | **학계는** 뭐라고 하나 | 기존 7건 → Zotero 파이프. 원문 PDF는 비공개(저작권), 공개면은 메타데이터+한국어 요약+DOI 딥링크. OA 논문만 원문 링크 |

## 그룹 4. 회복 (실용)

| 페이지 | 답하는 질문 | 상태 |
|---|---|---|
| **회복자원** /recovery | **어디서 도움받나** | 기존 5건 → 전국 디렉토리 100건+. 공공 목록 크롤링(중독관리통합지원센터 63개소, 스마트쉼센터, 도박예방치유원, 게임과몰입힐링센터, 마약퇴치운동본부) + 당사자 지식(GA·AA 자조모임, 라파공동체 등 신앙기반 공동체). 연 1회 크롤링 갱신 |

## 홈

관측소 현황판(완성, summary API 연동) + 부처 분산 지도(완성) + 각 그룹 대표 콘텐츠. 헤드라인 유지: "중독은 개인의 도덕 실패가 아니라, 사회 전체의 구조적 위험 시그널입니다."

## 중복 판정 규칙

같은 대상이 여러 페이지에 나타날 수 있으나 **역할이 달라야 한다**. 예: 사감위는 소스 지도에 "출처"로, 그 실태조사는 정책문서에 "산출물"로, 그 수치는 지표에 "데이터"로 존재하고 서로 링크된다. 연결 고리는 `source_id` FK (documents·research·observations·lab 결과물에 nullable 컬럼).

# 제3장. 파이프라인 — 자료가 흐르는 길

정관 1·2조의 구현. 모든 파이프는 같은 형태를 가진다:

```
감지/수집 (자동) → 정제/초안 (AI) → 승인 (사람, 하루 5분) → 게시 (자동)
```

| 파이프 | 감지/수집 | AI 단계 | 승인 지점 | 상태 |
|---|---|---|---|---|
| P1 발표 감시 | 크론 (매일 09시 + 월요일 irregular) | — | Discord 알림 확인 | ✅ 가동 중 |
| P2 지표 수집 | EUDA CSV·WHO GHO API·공공데이터포털 | 단위·기간 정규화 | 신규 지표 첫 등록 시 | M3 |
| P3 정책문서 | P1 알림 트리거 | DeepSeek 요약·분류 초안 | 게시 전 승인 | M3와 병행 |
| P4 연구자료 | Zotero API (운영자가 담은 논문) | DeepSeek 한국어 요약 초안 | 게시 전 승인 | 배포 후 |
| P5 분석실 | P2 데이터 도착 트리거 | Statory 엔진 분석 + 초안 | 게시 전 승인 | M4 이후 |
| P6 회복자원 | 연 1회 크롤링 | 변경분 diff | 변경분만 확인 | 배포 전 1회 + 연례 |
| P7 확산 | 게시 이벤트 | 중독뉴스 기사 초안 | 기사 승인 | 중독뉴스 연동 |

**승인 UI 원칙**: 승인은 Discord에서 시작해 관리자 페이지 버튼 하나로 끝나야 한다. 승인에 5분 이상 걸리는 파이프는 설계 실패로 간주하고 재설계한다.

## 의사결정 규칙

Claude(챗·Code 모두)는 자율 결정 후 보고에 결정 사항과 근거를 명시한다. 사용자 확인은 (a) 되돌리기 비싼 제품 결정(비용·공개·대외 노출) (b) 사용자만 아는 정보에 한한다.

# 제4장. 기술 아키텍처

## 결정: 프론트 전면 재구축, 백엔드 유지

**근거** (2026-07 조사): 현 프론트는 CRA(공식 지원 종료) + 글로벌 App.css 단일 파일 + SSR 불가(SEO 불가). 콘텐츠 19건·방문자 0명인 지금이 재건축이 가장 싼 시점. 반면 백엔드(NestJS)는 M1·M2로 방금 검증된 자산 — API만 제공하면 프론트 교체와 무관.

| 층 | 기술 | 비고 |
|---|---|---|
| 프론트 | **Next.js** (신규) | Statory·중독뉴스와 동일 스택 — 1인 운영에서 학습 전이가 결정적. SSR/SSG로 SEO. Vercel 배포 |
| 백엔드 | **NestJS** (유지) | sources 모듈·크론·API 그대로. `/api` prefix 컨트롤러별 |
| DB | Postgres → **Supabase** (Singapore) | 중독뉴스와 동일. 시드 멱등이라 재시딩으로 이전 |
| 파일 | Supabase Storage | PDF 원문은 비공개 버킷 (Render 디스크는 재배포 시 소실) |
| 배포 | Render(백) + Vercel(프론트) | 중독뉴스 검증 조합 재사용 |
| 알림 | Discord `#중독사회-관측소` | ✅ 가동 중 |
| LLM | DeepSeek 주력 | LLM_POLICY_JSON 패턴. Qwen/GLM A/B는 별도 트랙 |

## 선행 필수: M2.5

배포 전 `synchronize: false` 전환 + TypeORM 마이그레이션 인프라 구축. 현재 synchronize=true 하드코딩·환경분기 없음 — 운영 DB에서 데이터 손실 위험. **배포 결정과 동시에 최우선.** 특히 observations(데이터 누적 테이블) 생성 전에 완료할 것.

## 기존 코딩 원칙 (유지)

코드 읽고 행동(추측 금지) / add-only / "지금만 넘기자" 금지 / 한국어 주석 / 최대값·최소값(사이시옷 없음) / 크론 throw 금지·소스별 격리 / 지시서는 완주형(중간 질문 없이 자율 판단·근거 보고).

# 제5장. 이중언어 전략

## 중독사회: 처음부터 ko/en

- 근거: "세계에 없는 사이트"는 영어 없이는 "한국에 없는 사이트"에 그친다. Lancet이 WHO에 도박 포함을 요구하는 지금, 전 중독 영역 + 동아시아 데이터 관측소는 국제적 빈자리.
- 데이터는 번역 손실이 최소 (숫자는 만국 공통). title_en·name_en 필드 이미 존재/설계됨.
- **Next.js 재구축 시 URL 구조에 locale을 처음부터** (`/en/...`). 나중에 붙이면 전 페이지 재작업.
- 분석실 차트는 라벨 교체만으로 영어판 (Statory 브랜디드 SVG).

## 중독뉴스: 당분간 한국어 주력

- 뉴스는 데이터와 달리 맥락 번역 비용이 크다 (국정감사·사감위 등은 설명 없이 번역 불가). 한국어 독자층도 아직 형성 전.
- **문만 열어둔다**: ① 백과사전 172항목(이미 ko/en)을 영어 검색 선봉으로, ② 기사 스키마에 title_en·summary_en nullable 컬럼만, ③ 전환 트리거 = 중독사회 영어판에 해외 유입 발생 → 주간 영어 다이제스트 1편부터 → 전체 번역은 그 후.

## 역할 분담

| | 한국어 | 영어 |
|---|---|---|
| 중독사회 | 국내 기자·연구자·정책 | 국제 연구자·기관 |
| 중독뉴스 | 국내 독자 (주력) | 백과사전만 → 추후 다이제스트 |

# 제6장. 생태계 — 세 사이트의 선순환

```
관측소가 발표 감지 (중독사회 크론)
  → 지표 수집 (M3)
  → Statory 엔진이 분석 (중독랩)
  → 분석실에 축적 (중독사회)
  → 중독뉴스가 기사로 확산
  → 독자가 근거를 따라 중독사회로, 엔진을 따라 Statory로
```

- 중독사회 = **신뢰의 축** (데이터·근거)
- 중독뉴스 = **도달의 축** (사건·기사·SEO 유입)
- Statory = **엔진이자 수익의 축** — 분석실은 Statory의 살아있는 공개 포트폴리오. EXIT 전략(MRR 기반 매각) 관점에서 "자사 엔진으로 실제 사회 데이터를 분석·축적한 공개 실적"이 된다.
- 통놀·라파TV = 추가 유입구 (영상 콘텐츠 → 사이트 링크).

**상호 링크 규칙**: 중독뉴스 기사의 모든 수치는 중독사회 지표 페이지로 링크. 중독사회 지표·분석실은 관련 중독뉴스 기사로 링크. 분석실 결과물은 "Powered by Statory" 명기.

# 제8장. 불변 원칙 (위반 시 롤백)

1. ❌ 예시·가상 숫자 화면 노출. 없으면 "수집 중".
2. ❌ 지수(Index) 산출 — M6 조건 충족 전까지. 데이터가 쌓일수록 "한국 몇 점" 유혹이 커진다. 가중치 정당화 없는 점수는 공격당하는 순간 관측소 전체의 신뢰를 무너뜨린다. 비교(M5)까지만.
3. ✅ 모든 수치에 원본 딥링크 (observations.source_url NOT NULL).
4. ✅ 정의 없는 지표 금지 (indicators.definition_ko NOT NULL).
5. ✅ 1차 소스(reliability=1)만 지표로. 언론은 맥락용.
6. ❌ 논문 원문 PDF 공개 재배포 (저작권). 메타데이터·요약·딥링크만 공개. OA 예외.
7. ❌ WHO 자료 상업적 이용 (CC BY-NC-SA 3.0 IGO, 출처표시 필수).
8. ✅ 검수 없는 자동 게시 금지 — 정관 2조의 단서. AI는 초안까지, 게시는 승인 후.
9. ❌ 콘텐츠 복제 축적 (Statory↔중독사회, 중독뉴스↔중독사회). 프록시와 링크로 연결, 사본 금지.
10. ❌ 웹훅 URL 등 비밀값 노출.
11. ✅ 감지·감시 이력 보존 (source_events append-only). 크론의 확인·발간감지·변경감지·차단·실패·예정일 이월은 전부 1행씩 남긴다. 덮어쓰기·삭제 금지. 소스 레코드는 "현재 상태"만 알려주므로 그것만으로는 "언제 무엇이 어떻게 바뀌었나"가 사라진다. Discord 알림은 이 이력의 표현일 뿐이며, 알림이 휘발해도 이력은 남아야 한다. *(AS-M3-LEDGER에서 신설. 코드 인용처: `source-event.entity.ts`, `sources.scheduler.ts`, `backfill-next.ts`, `1785200000000-CreateSourceEvents.ts`)*
12. ✅ 관리자용 쓰기·승인은 admin 권한만. 공개 회원가입은 항상 차단하며 신규 계정 기본 역할은 `user`다. *(AS-FIX-1 및 AUTH-001 — 감사 이전에는 익명 가입자가 곧바로 `admin`이 되어 관측치 승인까지 가능했고, 이는 원칙 8을 무력화했다. 상세: `docs/AUDIT-2026-08.md` 문제 #1)*

    **유일한 예외 — 서명된 검수 링크 (AS-PDF-RUN).** Discord 알림에 실리는 검수 URL은 로그인 없이 승인/폐기를 수행한다. 이는 원칙 12의 우회가 아니라 **권한 한 조각의 서명된 위임(capability)**이며, 아래 조건을 전부 만족할 때만 허용한다. 하나라도 깨지면 원칙 12 위반이다.
    - 범위: 특정 검수 배치 1건의 승인/폐기만. 다른 생성·수정·조회 불가.
    - 전달: Discord 관측소 채널 한정(웹훅 URL 자체가 비밀값 — 원칙 10). 토큰을 볼 수 있는 사람 = 이미 운영자.
    - 위조 불가: 서버 비밀키로 HMAC-SHA256 서명, `timingSafeEqual` 비교.
    - 만료: 기본 14일.
    - 1회성: 배치가 처리되면 재사용해도 0건.
    - **GET은 상태를 바꾸지 않는다.** 확인 화면만 렌더하고 처리는 POST에서 — 메신저의 링크 미리보기 크롤러가 자동 승인하는 사고를 막기 위함.

    근거: 검수(원칙 8)에 관리자 UI가 필요한데 운영자가 관리자 계정을 쓰지 않는다. 검수가 병목이면 수집 파이프를 켤 수 없고, 파이프가 멈추면 갱신 중단(제1 사망 원인)에 이른다. 구현·상세 주석: `backend/src/indicators/review-token.util.ts`.
